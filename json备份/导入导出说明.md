# ZZZ-HP 数据导入 / 导出说明

本文说明管理端与 CLI 的快照格式，以及如何用备份 JSON 同步到其他环境。

---

## 1. 有哪些导出类型

| 类型 | `kind` | 内容 | 管理端入口 | CLI / API |
|------|--------|------|------------|-----------|
| 赛季内容快照 | `zzz-hp-season-snapshot` | 某模式的期数怪物、环境 Buff、日期，临界含节点 | 各模式内容管理 → 导入/导出 | `GET/POST /api/admin/season-content/export\|import` |
| Buff 表 | `zzz-hp-buff-table` | 危局 / 防卫 / 临界环境 Buff 整表（含效果块） | 环境 Buff 管理 →「导入 / 导出」 | `npm run export:buff` / `import:buff`；`/api/buff/export\|import` |
| 怪物基础库 | `zzz-hp-boss-info` | `boss_info`（含场地 Buff 多套、失衡易伤、高抗性、异常条系数等） | 怪物基础库 →「导入 / 导出」 | `npm run export:boss-info`；`/api/boss-info/export\|import` |

另有「从 boss 同步」：管理端怪物基础库列表 → **从 boss 同步**，把各期 `boss` 表里有的名字补进基础库，并把 `/UI/` 路径尽量换成本地 `/boss_image/...`。

## 3. 推荐导入顺序（整库对齐）

1. **怪物基础库**（`boss-info`）— 先有共用基础数据与场地 Buff 多套  
2. **Buff 表**（`buff-table`）— 或依赖下面赛季快照里的 buff 段  
3. **赛季内容**（危局 / 防卫 / 临界各一份）— 写入各期 `boss`、`buff`、日期、临界节点  

若只想更新环境 Buff，只导 Buff 表即可。  
若只想更新某模式排表，只导对应赛季快照即可。

## 4. 管理端操作

### 4.1 赛季内容（危局 / 防卫 / 临界）

1. 登录管理端，进入对应模式内容页。  
2. 打开导入/导出面板。  
3. **导出**：可选当前期或全部，下载 JSON。  
4. **导入**：选择备份 JSON → 确认。  
   - 危局用 `zzz-hp-crisis-all*.json`  
   - 新·防卫战用 `zzz-hp-defense-new-all*.json`  
   - 临界用 `zzz-hp-deduction-all*.json`

### 4.2 环境 Buff 表

1. 管理端 → **环境 Buff 管理** →「导入 / 导出」。  
2. 导出可按模式筛选；导入默认增量（按 id 或 模式+版本+期数+名称）。  
3. 勾选「覆盖写入」会先删目标范围再插入，**不可撤销**，先备份。

### 4.3 怪物基础库

1. 管理端 → **怪物基础库** →「导入 / 导出」。  
2. 默认按 id / 怪物名增量；覆盖会清空 `boss_info` 再写入。  
3. 导入后如缺图：选「临界」→ **从 boss 同步**。

**异常条系数（`anomaly_bar_coefficient`）**：快照自 2026-10 起携带该列（导出列为 `anomalyBarCoefficient`）。
空值表示「未配置」，由后端内置默认表解析（`zzz-hp-backend/src/utils/anomalyBarCoefficient.js`），
所以**旧快照（没有这一列）导入后常见 Boss 仍能显示正确系数**，只有手工覆盖过的值需要靠快照传递 ——
这也是「导出一份给其他环境」时应该带上它的原因。旧文件不做必填校验，导入即按空处理。

## 5. CLI（Buff 表）

在 `zzz-hp-backend` 目录：

```bash
# 导出当前库 → scripts/data/buff.json
npm run export:buff

# 增量导入（默认读 scripts/data/buff.json）
npm run import:buff

# 指定文件
npm run import:buff -- --file scripts/data/snapshots/2026-08-25/zzz-hp-buff-table.json

# 覆盖整表（可加 --mode crisis|defense|deduction）
npm run import:buff -- --replace
npm run import:buff -- --replace --mode deduction
```

仓库里 `scripts/data/buff.json` 已与 `2026-08-25` Buff 表快照对齐，可供云端/同事直接 `import:buff`。

### 5.1 怪物基础库（CLI）

```bash
# 导出当前库 → scripts/data/boss-info.json
npm run export:boss-info

# 指定输出文件（例如按日期归档）
npm run export:boss-info -- --file scripts/data/snapshots/2026-11-01/zzz-hp-boss-info.json
```

与 `export:buff` 同构：直接调用 `src/utils/bossInfoSnapshot.js` 的 `exportBossInfoSnapshot()`，
与管理端「怪物基础库 → 导出」是同一份实现，字段范围一致。
`2026-11-01` 目录下的怪物基础库快照即由该命令生成（155 条），可与 `2026-08-25` 对照差异。

## 6. 增量 vs 覆盖

| 方式 | 行为 | 适用 |
|------|------|------|
| 增量（默认） | 有则更新、无则新增；一般不删文件里没有的行 | 日常补丁、合并他人数据 |
| 覆盖 | 先清空目标范围再写入 | 强制与某份备份完全一致 |

覆盖前务必先导出一份本地备份。

## 7. 给其他人更新时怎么发

任选其一：

1. **发 JSON 文件**（你管理端刚导出的，或本目录 `2026-08-25` 备份）— 对方用管理端导入。  
2. **拉本仓库对应分支**（如 `3.1.7.1` / `3.1.7.2`）— 使用  
   `zzz-hp-backend/scripts/data/snapshots/2026-08-25/`  
   与 `scripts/data/buff.json`。  

对方需要：已部署含导入功能的版本、管理员账号、数据库可写；图片资源按路径自备或另拷。

## 8. 与 SQL 云导入的关系

`zzz-hp-backend/scripts/data/cloud-import/` 下的 `.sql` 适合整表替换式运维导入。  
日常协作更推荐本文的 **JSON 快照**（可增量、可按模式、与管理端一致）。

详见同目录下的 `README-导入说明.txt`（偏 SQL / PowerShell）。
