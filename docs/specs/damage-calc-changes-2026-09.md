## 2. 现行行为口径

### 2.1 面板来源：两份平级、一份生效

- 每个角色存**两份**局外面板：`importedPanel`（面板导入）与 `affixDerivedPanel`（词条导入），互不覆盖；
  `active` 指向当前生效那份。实现见 `zzz-hp/src/utils/agentPanelSources.ts`。
- 下游（伤害计算、扫掠柱图、最优分配、增益计算）只接收**一份** `PanelStats`，**不接收也不查询来源**；
  「来源」只是界面元数据。
- 选中那份没有数据时，取值**回落**到另一份；界面标注按回落后的**实际来源**标（见 2.3）。

### 2.1.1 两条必要条件（2026-09-12 确立，所有者口径）

1. **不点导入 → 面板产生不出来**；
2. **没有面板 → 没有伤害**。

这两条是**代码层**约束，不是「禁用按钮」那类界面拦截（原话：「而不是，不选不让点导入，这个我觉得不是关键」）。

**约束一：写面板的入口只剩三类，且都是用户动作**

| 写入点 | 触发 |
|---|---|
| `writePanelSource`（`DamageCalcPage` 两处） | 用户点「确定导入」 |
| `setActivePanelSource` | 用户手动切换激活来源 |
| `writeAffixInputsIntoSource`（`damageCalcHistory.ts` 一处） | 读旧格式时的一次性数据迁移 |

改前存在的这些路径**已全部删除**：`ensureAgentExternalPanel`（用角色基础面板造一份并激活）、
`flushImportedPanelForAgent` / `flushAffixOnto*` / `commitDerivedPanelForAgent` / `migrateSnapshotAffixOntoSlots`
（自动写回）、`agentPanelSources.updatePanelSourceValues`（专供自动写回的写入口）。
`test-panel-dual-source.mjs` 用源码断言钉死这条边界。

**约束二：无面板 → 空面板 → 伤害为 0**

- 无面板记录时，`PanelCalcSection.resolveExternalPanelForSlotIndex` / `panelBuffCalc.resolveExternalPanelForSlot`
  一律给 `createEmptyExternalPanel()`（用户录入字段全 0；乘区入口保持中性 ×1，避免把公式乘成 0），
  **不再回落**到占位毕业面板（生命 9873 / 攻击 4008）或 live 编辑器。
- 仅归零面板**不够**：Buff 里的固定攻击 / 暴击仍会算出量（实测残量约 2.5 M，占当时总伤 3.5%）。
  因此 `evaluateOptimalEventDetail` 增加 `requirePanel` 选项：伤害页四个入口
  （`syncHitSummary`、`selectedEventEvalDetail`、伤害过程面板、`useDamageProcessEvents`）传 `true`，
  出手角色没有面板时该 hit 直接不出伤；异常类还要求强度提供者也有面板。
- **最优词条分配链路不传 `requirePanel`** —— 它本来就要能「无基准面板」推导，维持现状。
- 主 C 没面板时，伤害计算区显示提示：「当前角色还没有面板（局外面板为 0，伤害不计算）——请点顶部「导入」录入或截图识别后「确定导入」」。

### 2.1.2 空就是空（2026-09-12）

- **面板导入表单**：12 项录入字段留空即 `null`（不是 0、更不是占位面板）；没填齐时点「确定导入」
  只提示「面板还缺 N 项没填：…」并拒绝写盘。截图识别只写识别到的项，其余留空。
- **4/5/6 号盘主属性**：下拉含「未选择（空）」项，**默认为空**；空就按「不提供该主属性」计，
  不再要求「必须选满才能导入」。**面板导入与词条导入均可填写**（面板导入不参与局外数字计算，
  写入后供词条分析上限 / 组合试算使用；截图识别到时会回填）。
- 「没填」与「填了 0」严格区分：填 0 也算填了。

### 2.2 招式流程「伤害面板」三选项

| 选项 | 主 C 局外面板来源 | 何时可用 |
|------|-------------------|----------|
| ① 角色配置面板 | 角色配置里那份激活面板（默认） | 始终 |
| ② 词条分析 · 最优分配 | 求解出的词条数叠加在基准面板上 | 本次会话求解过，且两侧签名一致 |
| ③ 词条分析 · 当前点击柱 | 当前点击柱的词条数叠加（不点柱时用第一根） | 本次会话点过柱或扫掠过，且签名一致 |

选项 ②③ 的数据**只活在内存**（词条分析产物不落盘），刷新后回到禁用并回落 ①。

**可用性判定是安全网，不是主动闸门**（2026-09-11 实测）：

| 改了什么 | 实际行为 | 原因 |
|----------|----------|------|
| 共享响应式对象上的值（敌方防御、Buff 勾选） | ② **保持可用**，数值随配置实时重算 | 两侧读同一对象，签名同时变、值也同时变 |
| 原始值 prop（切换编辑槽位、邦布、伤害类型、基础伤害来源） | ② **变禁用**并回落 ① | 模块被 `v-if` 停用后 props 不再 patch，签名停在旧配置 |

两条路都是安全方向；未发现「启用着却是旧数」的路径。

**② 的语义**：用**求解出的词条数**叠加在**当前**基准面板上。基准面板之后变化时，条数仍是那次求解的结果
（与选项说明文案一致）；若将来要改成「基准一变就作废求解结果」，属于产品口径变更，需先确认。

### 2.3 顶部槽位卡片

- 悬停任一个槽位卡片：显示该角色的**局外面板**与**局内面板**（局内随 Buff 增益实时重算），
  面板 / 词条 / 最优三个模式口径一致。
- 标题行右侧两枚胶囊「面板导入 / 词条导入」：生效那份绿框，另一枚灰，悬停有说明。
  胶囊只做**标注**，切换仍在导入弹窗的「面板来源」里。

## 3. 招式计算链路统一（技术要点）

统一前有两条各自独立的「算一击」实现与两份缓存，数值口径容易分叉。现在：

- 一击的计算统一走 `evaluateOptimalEventDetail`（`zzz-hp/src/utils/optimalAffixAlloc.ts`），
  招式上下文由 `buildSkillContextFromHit`（`zzz-hp/src/utils/resolvedHit.ts`）构造；
  面板侧删除了重复实现（`buildHitCalcInput` 及其专属辅助），净减 336 行（`40f3d76` + `f768d71`）。
- 缓存统一为一份 `zzz-hp/src/utils/hitEvalCache.ts`：
  键 = 招式指纹 + 上下文令牌 + 主 C 局外面板 + 是否带明细，上限 500 条；
  序列化按排序键生成，两条路径同输入产生同一个键。
- 合并期间修掉两个真问题：签名取自 `ctx` 时**没有响应式依赖**（改敌方防御 70 条全不变，静默命中旧值）；
  `JSON.stringify` 键序不同导致同面板产生两份缓存条目。

## 5. 未验证 / 遗留

1. **真·多柱点选**下选项 ③ 的数值跟随未实测：本方案的扫掠在当前配置只产出 1 根柱，
   仅验证了「页级 → 面板侧」这条链路。
2. 面板侧与最优侧的**上下文签名仍是各自一份**，同一份面板在缓存里占两行
   （数值正确，只是没共用）；要真正共用需再收口一次。
3. **编辑面板数值后 ② 的可用性**：读代码判定为「改到生效那份面板 → 禁用」（安全方向），未在界面上实测。
4. `includeDetails: false` 会跳过蕾米埃尔自辐射的整块面板计算（`optimalAffixAlloc.ts:1175`），
   明细层有回落分支（`DamageResultDetail.vue:397`：拿不到自辐射面板时会退到别的面板）。
   若将来要在明细里展示自辐射面板，需先显式定义产物边界。
5. **草稿写盘策略**：页级 deep watch（任何状态变化 400ms 写草稿）不区分「用户操作」与「程序内部抖动」。
   当前内存已不会自变脏，暂无实际危害；收紧需在十余个动作点各埋一次写盘，与「不加重代码」相冲，**保持现状**。
6. **旧数据不动**：以前某次自动写回留在盘上的占位面板仍是历史数据，导入时会被
   `isPlaceholderExternalPanel` 拦下（提示「请先填写或识别面板」）；按所有者口径
   「用户数据的问题不写代码去猜、去修」。
7. **链路外的零引用导出保留**：`src/api/*`、`src/data/*`、`defense*`、`elementIcons`、`guestbook*`
   等模块另有 25 个零引用导出，按所有者决定「吃不准的留着，只要不影响计算」，**未删**。

## 6. 最优分配：自适应 Beam（2026-09-16）

> 详细口径在开发手册 `dev-docs/词条最优分配.md`（不进仓库）。本节是仓库内摘要。
> 本节取代原先的「单一贪心 + 穿透专路」实现（旧实现摘要见本章文末，行不删）。

**要修的漏解**：5 号穿透 24% 和 2 件套穿透 8% 单独 +1 都不如同槽增伤，贪心先锁增伤，河豚 + 5 号穿透这套常见配进不去。另外单路贪心一旦起步选错就回不来。

**现行搜索**（2026-09-17 第三轮定稿）：同一预算下保留**多条完整分配路线**，最后比总伤（**没有换档精修**）。

- 按**已用词条数**（不是「加了几次」）分桶推进；每个存活状态扩展候选池里所有当前可用条目。
- 按**规范化分配**去重；同一档数下按**三件套**定宽度：**累计提升比例**筛 → 不足**最小保留路线**条时按累计提升补足 → 超过**最大保留路线**条时按累计提升截顶。
- **没有自适应 B**：宽度只由三件套决定，同一份参数在任何机器上留同样的条数（可解释、可复现）。
- **预算只当刹车**：只挡在每次真实评估之前（缓存命中不计价），本层按总伤从高到低开、花光为止；撞预算不再停掉整个搜索。
- **穿透专路**：已启用则锁 `main:slot5:penRate` / `set:penRate:8`（绕过门槛与上下限），在带穿透率的面板上重测、形成独立候选池，再跑同一套 Beam，和普通路比最终总伤。
- 提升率两条路都用「一个词条都没分」的总伤当分母。

**五个用户参数**（取代「最低收益比例 + 候选宽度」）：

| 参数 | 含义 |
|---|---|
| 初始候选门槛 | 按**单档收益**只跟**本组最高**比，永久淘汰太弱的条目 |
| 候选兜底 | 每组按单档收益排前 N 名的条目一定保留（默认 5） |
| 路线保留比例 | 同一档数下只留接近最好的那批分法 |
| 最小保留路线 | 比例筛完不足这么多条时按累计提升补足（下限） |
| 最大保留路线 | 比例筛完超过这么多条时按累计提升截顶（上限，防爆宽度的唯一保险） |

**门槛为什么量「单档收益 × 组内最高」**：量「1 档边际 / 本路最佳单档」时，cap=1 的主属性（24% 穿透 / 30% 增伤）占据分母，把「单档值小但能连吃多档」的副词条整批筛掉（46 档只花得掉 10 档、总伤腰斩）；把标尺换成**同组最高**并加**候选兜底 5** 之后质量回到 100%。

**预设**（2026-09-17 定稿）：

| 预设 | 门槛 | 比例 | 最小–最大保留 | 备注 |
|---|---|---|---|---|
| 快速 | 80% | 95% | 1–2 | 最窄，省算力 |
| 均衡（默认） | 50% | 90% | 2–5 | |
| 精细 | 20% | 50% | 4–8 | 最宽 |

**为什么必须有上限**（2026-09-17 实测）：比例线是「相对本层最佳」画的，同层常常一大批路线都在这条线以内 —— 去上限那版真机实测 **34 档只走完 9 层、20 万预算只花掉 3.9 万、`truncated`**（宽度暴涨 → 旧刹车的最坏估算爆表 → 提前 break）。上限截顶记 `routeCapDropped`，算设计内行为、不算截断。

**游戏专用**：付费判定 =「该主属性字段在副词条池里也有同 target 条目」—— **4 号位 6 条全付费**（爆伤 / 暴击 / 攻击 / 生命 / 精通 / 防御），5/6 号位只认攻 / 生 / 防（增伤 / 穿透率 / 异常掌控 / 冲击力 / 能量恢复在副词条池里没有对应条目）。付费 = 总分配多扣 x 档，并把对应副词条上限扣 5。4 号位恒付费，故外层只枚举 5/6 = **4 个口袋**，每袋都完整跑 Beam、独立公平预算，最后按总伤取最高。结果给出胜出口袋与各袋合计计算量。已经买了 5 号攻/生/防的口袋锁不到 24%（那个口袋没有 `main:slot5:penRate`），只会锁 2 件套 8%。

**计算量**：`maxWorkUnits` 是总刹车，默认 **200000**。一次评估计价 = `1 + 命中数`，缓存命中不计入。预算**只挡在每次真实评估之前**（按总伤从高到低开、花光为止），**不参与宽度决策**。可手动停止。

**结果文案**：计算量花完（后面的层开不动）才标「截断」；**上限截顶不算截断**（显示「上限截掉 N 条」）。「跳过精修」那行已随换档精修一起删掉。

**验证**（2026-09-17 第三轮）：`test-affix-optimizer.mjs` **153 passed / 0 failed**（含上限截顶记账、上下限矛盾时上限优先、界面五参数透传的源码级守卫、预设值 == 用户口径）；`vue-tsc` / ESLint exit 0；`npm test` 全套见提交说明（`test-affix-cache-key` 是计时敏感用例，满载会误报、空载即绿）。fixture `zzz-hp/fixtures/pen-rate-alloc/ye-shiyuan-pen-rate.json`（「不带东西」）选出 24+8。
